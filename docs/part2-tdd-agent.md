# Часть 2. TDD и LLM-агент

## Задача

Реализовать расчёт суммы заказа в `src/shop/checkout.py` по требованиям из
[`src/shop/specs/checkout.md`](../src/shop/specs/checkout.md). В стартовой версии
репозитория сигнатуры и константы заданы, а тела двух функций — заглушки:

```python
def validate_order(
    lines: list[dict[str, str]],
    promo_code: str = "",
    shipping_city: str = "",
) -> str | None:
    """Return a human readable reason why the order is invalid, or None if it is fine."""
    ...


def calculate_order_total(
    lines: list[dict[str, str]],
    promo_code: str = "",
    shipping_city: str = "",
) -> int | None:
    """Return the order total in kopecks, or None if the order is invalid."""
    ...
```

В стартовой версии `tests/test_checkout.py` лежат заготовки под остальные случаи:
их нужно дописать по одной, проверяя каждое требование спецификации. После
завершения работы все эти тесты должны содержать исполняемые проверки.

## Кто что пишет

| Кто       | Что делает                                             |
| --------- | ------------------------------------------------------ |
| **Вы**    | читаете ТЗ, формулируете ожидания, пишете тест        |
| **Агент** | превращает ваш красный тест в зелёный минимальным кодом |

Это не распределение по экономии. Тест — исполняемое утверждение о требовании, и
написать его выгоднее и быстрее, чем проверять, придумал ли агент то же
требование. Агент хорош в переводе намерения в код и плох в догадках о
намерении.

Цикл: красный тест → минимальный код → зелёный → отдельный коммит на рефакторинг,
и снова. Один подход — один коммит с тестом, один — с кодом.

## Как настроить агента

Любой агент, умеющий читать файлы и запускать команды: opencode, Claude Code,
Codex CLI, Aider, Cursor. Правила проекта лежат в `AGENTS.md` — скажите агенту
прочитать этот файл целиком. Дайте ему путь к ТЗ и ровно один красный тест, который
нужно сделать зелёмым.

## Как проверять

```bash
./scripts/check-part2.sh
```

| Джоба               | Что требует                                                       |
| ------------------- | ----------------------------------------------------------------- |
| `tests`             | весь набор зелёный, то есть часть 1 не сломана                   |
| `checkout-coverage` | покрытие `shop.checkout` не ниже 90 %                            |
| `tdd-history`       | тестов достаточно, в каждом есть `assert`, тесты раньше кода     |

Проверку порядка выполняет `scripts/check_tdd_history.py`: она смотрит на историю
git и сравнивает два коммита — тот, где тестов стало достаточно, и тот, где
заглушка исчезла из реализации.

Если репозиторий склонирован с `--depth=1`, эта проверка предупреждает и
пропускается: история недоступна. Для полной проверки нужен обычный клон.

## Что должно получиться

`./scripts/check-part2.sh` — обе проверки зелёные. Плюс `./scripts/check.sh`
целиком: правила части 1 продолжают работать и для нового кода.
